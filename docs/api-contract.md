# Local application API contract

All `/api/*` endpoints require a session except POST `/api/session`. No credentials, file paths or raw upstream errors are returned. Runtime has no personal defaults.

- GET `/api/dashboard?range=7|30|90|all`: `{dates: [YYYY-MM-DD], repos: [Repository], updatedAt: ISO|null, collecting: boolean, credentialConfigured: boolean}`. `all` bounded to available retained data (max 3660 points). Repository `{id:string, owner,name,visibility:'public'|'private',archived:boolean,language:string|null,description:string|null,url:string,metrics:{[key]:Metric}}`.
- Metric `{label,kind:'event'|'balance',unit,value:number|null,delta:number|null,points:[{date,value:number|null}],coverage:{start:string|null,end:string|null,complete:boolean},status:string,lastSuccess:ISO|null,observedAt:ISO,source:string}`. Dates align to dashboard dates. Unknown days are null, not zero; missing families absent. Event totals sum known observations, coverage incomplete when range isn't covered. Balance value is the latest retained actual observation even when outside the chart window; `observedAt` identifies that observation and does not add a synthetic chart point; delta only when defensible observed endpoints. Chart gaps must remain gaps. A one-point balance is a point, not synthetic history.
- GET `/api/status`: `{collecting,credentialConfigured,lastAttempt,lastSuccess,nextRun?,runs:[{repository,metric,status,lastAttempt,lastSuccess,message}],rateLimit?}`. Sanitized diagnostics; no secret paths.
- GET `/api/events?limit=100`: `{events:[{id,repository,type,date,title,url,author?}]}`. Metadata only, no email/body/code. Bound to 500.
- GET `/api/details?repository=ID&metric=KEY&range=7|30|90|all&offset=0&limit=50`: authenticated, persisted-data-only detail lookup; never triggers an upstream request. Response `{items:[{id:string,date:YYYY-MM-DD,title:string,url:string,author?:string}],total:number,hasMore:boolean,offset:number,limit:number,kind:'events'|'snapshot'|'observations',observedAt:ISO|null,status:string,complete:boolean}`.
  - `repository` is the exact active watch ID from the dashboard, not `owner/name`. Unknown or paused watches return 404. Invalid/missing IDs or metrics, invalid ranges, non-integer pagination, duplicate named query parameters, negative offsets, or limits outside 1–100 return 400. Decimal query integers must be canonical (`0`, `1`, etc.; no whitespace, signs, exponent notation or leading zeros). Defaults: range `30`, offset `0`, limit `50`.
  - `commits`, `merged_prs`, `releases`: `kind:'events'`. Filter by exact repository AND metric AND inclusive dashboard UTC date bounds (including the same retained-data/3660-day cap for `all`). Order by date descending, then stable ID ascending. `total` counts all matching records before pagination. `complete` requires daily coverage throughout the selected range and a successful latest collection; a failed refresh retains prior records and their observation time but reports its failure status and `complete:false`.
  - `issues`: `kind:'snapshot'`. The **current retained open-issue snapshot**, excluding pull requests, independent of chart range; `date` is the issue's creation day, not an opening event in the selected range. Order by creation day descending, then issue number ascending. `observedAt` identifies the retained detail snapshot (null if none), not the latest attempt. Replace records atomically only after complete successful pagination and valid detail metadata; failed, truncated or malformed fetches retain previous records. A successful empty snapshot has `total:0,complete:true`. Missing issue numbers/creation dates can still yield a valid count observation, but details report `status:'details_incomplete',complete:false` and retain the prior records/time. Consequently the retained detail total can differ from a newer count-only dashboard observation. Existing count-only databases remain usable and acquire issue records on the next complete collection.
  - `stars`, `forks`, `views`, `clones`, `star_activity`: `kind:'observations'`, `items:[]`, `total:0`, `hasMore:false`. The frontend uses existing dashboard points rather than inventing individual identities. Completeness reflects selected daily observation coverage and latest collection status.
  - All kinds report `status:'not_collected',complete:false` when never collected. Pagination does not change completeness; `hasMore` means more retained matching records after this page. `observedAt` for events/observations is the latest retained metric observation on or before the dashboard end date. IDs are opaque stable strings; URLs are constructed from validated GitHub repository/record identifiers. Only minimal issue number/title/creation day/URL is persisted, never issue bodies, emails, or raw provider URLs.
- GET `/api/discover`: `{repositories:[{id,owner,name,visibility,archived,watched}]}`. Existing token's owned repos only; explicit chooser, no silent enrollment.
- POST `/api/watches` JSON `{repository:'owner/repo' or exact github.com URL,access:'public'|'token'}`: `{repository:Repository}`. Public explicitly anonymous metadata check; token lookup NEVER falls back anonymously. Deduplicate stable ID.
- POST `/api/watches/:id/pause`: pause without deleting history; paused watches leave the dashboard. Discovery reports them as not watched so explicitly re-adding resumes collection. JSON `{}`.
- POST `/api/sync` JSON `{}`: HTTP 202 `{started:true|false}`. Non-blocking bounded collection; UI polls persisted data rather than issuing GitHub calls on refresh.
- GET `/api/export?range=...`: CSV exported from current persisted dashboard; frontend may instead construct CSV for filtered scope. Escape formula-leading text and CSV quotes/newlines.
- POST `/api/session` JSON `{key:string}`: returns `{ok:true,csrf:string}` and HttpOnly SameSite=Strict session cookie. The startup unlock key is a private local file, never source or browser localStorage. Frontend consumes `#unlock=...`, removes fragment immediately, POSTs key once, then forgets it. POST `/api/session` with empty body under a valid session returns csrf. Show a clean locked screen if not authenticated; no automatic secret disclosure.
- All other mutations require `X-CSRF-Token` from session response and same-origin Origin. GETs stay same-origin. HTTP errors JSON `{error:generic message}`.

Backend module contract (`src/data.mjs`): `export async function createObservatory({dbPath,token='',fetchImpl=globalThis.fetch,now=()=>new Date(),maxPages=20})`; returns service with synchronous `dashboard(range)`, `status()`, `events(limit=100)`, `details({repository,metric,range='30',offset=0,limit=50})`, async `discover()`, `addWatch({repository,access})` (returns `{repository}`), `sync()` (single-flight internally), synchronous `pauseWatch(id)`, async `backup(destination)`, `close()`. `sync()` returns a sanitized summary; stores failures without erasing good history. `setNextRun(iso)` optional. Error objects may expose safe `.statusCode` and `.safeMessage` only. Public-only code must never require reading the host's GitHub CLI credentials.
