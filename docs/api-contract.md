# Local application API contract

All `/api/*` endpoints require a session except POST `/api/session`. No credentials, file paths or raw upstream errors are returned. Runtime has no personal defaults.

- GET `/api/dashboard?range=7|30|90|all`: `{dates: [YYYY-MM-DD], repos: [Repository], updatedAt: ISO|null, collecting: boolean, credentialConfigured: boolean}`. `all` bounded to available retained data (max 3660 points). Repository `{id:string, owner,name,visibility:'public'|'private',archived:boolean,language:string|null,description:string|null,url:string,metrics:{[key]:Metric},lastActivityAt?:ISO}`. `lastActivityAt` is the most recent retained actual event timestamp across metrics and feed, independent of chart range; absent when unknown. Never use sync/observation time, day-only legacy records, or a composite score as activity time.
- Metric `{label,kind:'event'|'balance',unit,value:number|null,delta:number|null,points:[{date,value:number|null}],coverage:{start:string|null,end:string|null,complete:boolean},status:string,lastSuccess:ISO|null,observedAt:ISO,source:string}`. Dates align to dashboard dates. Unknown days are null, not zero; missing families absent. Event totals sum known observations, coverage incomplete when range isn't covered. Balance value is the latest retained actual observation even when outside the chart window; `observedAt` identifies that observation and does not add a synthetic chart point; delta only when defensible observed endpoints. Chart gaps must remain gaps. A one-point balance is a point, not synthetic history.
- GET `/api/status`: `{collecting,credentialConfigured,lastAttempt,lastSuccess,nextRun?,runs:[{repository,metric,status,lastAttempt,lastSuccess,message}],rateLimit?}`. Sanitized diagnostics; no secret paths.
- GET `/api/events?offset=0&limit=100&range=all`: `{events:[ActivityEvent],total:number,hasMore:boolean,offset:number,limit:number,coverage:{complete:false,label:string}}`. Authenticated persisted-data-only read. Optional `repository=ID` is an exact active dashboard ID; unknown/paused IDs return 404, invalid IDs 400. Defaults: offset `0`, limit `100`, range `all`; `range=7|30|90|all` uses inclusive UTC days, and activity `all` includes all retained records through today (unlike capped chart arrays). Recommend pages of 50–100; preserve legacy limits through 500. Order: actual event timestamp descending, then stable opaque ID ascending; old day-only records retain day precision. `total` is the matching retained count before pagination, NOT a GitHub historical total; `hasMore` is whether more matching retained records follow. Paused watches never appear, including legacy `service.events()`.
  - Additional optional filters, all applied **before counting/pagination**: `visibility=all|public|private` (default `all`); `search` (default empty, max 200 characters, trimmed case-insensitive literal substring of `owner/name`, not a SQL pattern; controls rejected); `archived=true|false` (omitted means both, `true` only archived, `false` only nonarchived). For the UI's “Archived only” checkbox, send `true` when checked and omit when unchecked. Filters combine with AND.
  - Pagination integers must be canonical decimal, offset nonnegative/safe integer, limit 1–500. Empty/invalid values and duplicate named parameters (`repository`, `range`, `offset`, `limit`, `visibility`, `search`, `archived`) return 400. GET requests never call GitHub. Coverage is **always incomplete**, even when `hasMore:false`; provider caps, delay, permission failures, and local budgets prevent full-history claims.
- ActivityEvent `{id:string,repository:string,repositoryId:string,type:string,date:ISO|YYYY-MM-DD,title:string,url:string,author?:string,actor?:{login?:string,name?:string,url?:string},summary?:string,metadata?:{sha?:string,branch?:string,number?:number,action?:string,ref?:string,refType?:string,commitCount?:number,head?:string,base?:string},source?:string,observedAt?:ISO}`. New records use actual ISO timestamps; old rows may have only a day and no richer fields. `author` is a compatibility display string; metric records use their author, feed records use the event actor. Profile URLs are constructed only from validated logins, never provider URLs. Names are included only when actually provided, never inferred from `display_login` or email. Titles are bounded to 200 characters; summaries to 500; actor names to 100; refs to 255. Render as text, not HTML. Titles/names use one-line text normalization, separate from multiline descriptions: meaningful inline identifiers retain their content with backtick delimiters removed, and ordinary bullet descriptions retain their text. Descriptive text removes controls, bidi controls, email addresses and HTML tags. Descriptions discard fenced/indented code and contextual diff blocks (including context lines), not every line starting with `+` or `-`. Fenced blocks require a standalone closing fence of the same character and at least the opening length; embedded delimiter strings, shorter/mismatched fences and unfinished/truncated blocks never expose their contents. Recognizable statement/inline executable snippets are suppressed rather than used as prose; this is not a general-purpose source-code classifier. Refs are not Markdown: retain the exact validated ref (including literal backticks), or omit the whole value if invalid, too long, email-bearing, or containing controls/bidi/HTML delimiters; never truncate or sanitize a ref into a different identifier. No source/diff fields, raw response bodies, issue/comment/review bodies or email fields are retained.
  - `commits`: real first-line commit message title, optional remaining-message prose summary; `metadata.sha` is secondary, `metadata.branch` is the queried default branch (reachable there, not necessarily the branch where originally authored). `date` is GitHub's committer timestamp. If no title exists, use `Commit (title unavailable)`, never a hash as title. Legacy hash placeholders are shown as unavailable until a successful refresh can enrich them.
  - `merged_prs`: actual PR title, bounded description, author, merged timestamp, number, `action:'merged'`, head/base refs if supplied. `releases`: real release name/tag, bounded notes, author, published timestamp, tag ref; do not infer branch from `target_commitish`. Sources are `commits`, `pulls`, `releases`, or `github_events`.
  - Feed types include `stars`, `forks`, `pushes`, `pull_requests`, `merged_prs`, `releases`, `release_activity`, `issues`, `issue_comment`, `pull_request_review`, `pull_request_review_comment`, `commit_comment`, `discussion`, `ref_created`, `ref_deleted`, `public`, `gollum`, `member`. Future provider `*Event` types use descriptive snake_case without the `Event` suffix and minimal safe metadata. `WatchEvent` means a star, not a repository subscription. Pushes remain **push events**, not invented commit rows: their actor/time can differ from commit author/time, their commit array is not used, and current GitHub payloads often omit commit count. Never infer `commitCount`; include only an actually supplied `size`.
- GET `/api/details?repository=ID&metric=KEY&range=7|30|90|all&offset=0&limit=50`: authenticated, persisted-data-only detail lookup; never triggers an upstream request. Response `{items:[ActivityEvent|IssueRecord],total:number,hasMore:boolean,offset:number,limit:number,kind:'events'|'snapshot'|'observations',observedAt:ISO|null,status:string,complete:boolean,coverage?:{complete:false,label:string}}`. IssueRecord retains `{id,date:YYYY-MM-DD,title,url}`.
  - `repository` is the exact active watch ID from the dashboard, not `owner/name`. Unknown or paused watches return 404. Invalid/missing IDs or metrics, invalid ranges, non-integer pagination, duplicate named query parameters, negative offsets, or limits outside 1–100 return 400. Decimal query integers must be canonical (`0`, `1`, etc.; no whitespace, signs, exponent notation or leading zeros). Defaults: range `30`, offset `0`, limit `50`.
  - `commits`, `merged_prs`, `releases`: `kind:'events'`, using the same enriched record shape as Activity. Filter by exact repository AND metric AND inclusive dashboard UTC date bounds (including the same retained-data/3660-day cap for `all`). Order by actual timestamp descending, then stable ID ascending. These details are the authoritative metric endpoint records only, never extra feed-only records. `total` counts all matching records before pagination. `complete` requires daily coverage throughout the selected range and a successful latest collection; a failed refresh retains prior records and their observation time but reports its failure status and `complete:false`.
  - `issues`: `kind:'snapshot'`. The **current retained open-issue snapshot**, excluding pull requests, independent of chart range; `date` is the issue's creation day, not an opening event in the selected range. Order by creation day descending, then issue number ascending. `observedAt` identifies the retained detail snapshot (null if none), not the latest attempt. Replace records atomically only after complete successful pagination and valid detail metadata; failed, truncated or malformed fetches retain previous records. A successful empty snapshot has `total:0,complete:true`. Missing issue numbers/creation dates can still yield a valid count observation, but details report `status:'details_incomplete',complete:false` and retain the prior records/time. Consequently the retained detail total can differ from a newer count-only dashboard observation. Existing count-only databases remain usable and acquire issue records on the next complete collection.
  - `stars`, `forks`: after an activity collection attempt, `kind:'events'` returns genuinely observed named feed records filtered by selected UTC days (`all` includes all retained feed history). Always `complete:false` with explicit `coverage`; `status:'partial'` for a successful bounded collection, otherwise the actual feed error/status. `observedAt` is the latest retained record's collection time or null. These counts are NOT current star/fork balances and not complete histories; they do not replace chart observations. Before any activity attempt, retain `kind:'observations'` behavior.
  - `views`, `clones`, `star_activity`: `kind:'observations'`, `items:[]`, `total:0`, `hasMore:false`. The frontend uses existing dashboard points rather than inventing individual identities. Completeness reflects selected daily observation coverage and latest collection status.
  - All kinds report `status:'not_collected',complete:false` when never collected. Pagination does not change completeness; `hasMore` means more retained matching records after this page. `observedAt` for events/observations is the latest retained metric observation on or before the dashboard end date. IDs are opaque stable strings; URLs are constructed from validated GitHub repository/record identifiers. Only minimal issue number/title/creation day/URL is persisted, never issue bodies, emails, or raw provider URLs.
- GET `/api/discover`: `{repositories:[{id,owner,name,visibility,archived,watched}]}`. Existing token's owned repos only; explicit chooser, no silent enrollment.
- POST `/api/watches` JSON `{repository:'owner/repo' or exact github.com URL,access:'public'|'token'}`: `{repository:Repository}`. Public explicitly anonymous metadata check; token lookup NEVER falls back anonymously. Deduplicate stable ID.
- POST `/api/watches/:id/pause`: pause without deleting history; paused watches leave the dashboard, activity and details. Discovery reports them as not watched so explicitly re-adding resumes collection. JSON `{}`.
- POST `/api/sync` JSON `{}`: HTTP 202 `{started:true|false}`. Non-blocking bounded collection; UI polls persisted data rather than issuing GitHub calls on refresh.
- GET `/api/export?range=...`: CSV exported from current persisted dashboard; frontend may instead construct CSV for filtered scope. Escape formula-leading text and CSV quotes/newlines.
- POST `/api/session` JSON `{key:string}`: returns `{ok:true,csrf:string}` and HttpOnly SameSite=Strict session cookie. The startup unlock key is a private local file, never source or browser localStorage. Frontend consumes `#unlock=...`, removes fragment immediately, POSTs key once, then forgets it. POST `/api/session` with empty body under a valid session returns csrf. Show a clean locked screen if not authenticated; no automatic secret disclosure.
- All other mutations require `X-CSRF-Token` from session response and same-origin Origin. GETs stay same-origin. HTTP errors JSON `{error:generic message}`.

Backend module contract (`src/data.mjs`): `export async function createObservatory({dbPath,token='',fetchImpl=globalThis.fetch,now=()=>new Date(),maxPages=20})`; returns service with synchronous `dashboard(range)`, `status()`, legacy `events(limit=100)` returning **`{events:[...]}`**, `activity({repository?,range='all',offset=0,limit=100,visibility='all',search='',archived?})`, `details({repository,metric,range='30',offset=0,limit=50})`, async `discover()`, `addWatch({repository,access})` (returns `{repository}`), `sync()` (single-flight internally), synchronous `pauseWatch(id)`, async `backup(destination)`, `close()`. `sync()` returns a sanitized summary; stores failures without erasing good history. `setNextRun(iso)` optional. Error objects may expose safe `.statusCode` and `.safeMessage` only. Public-only code must never require reading the host's GitHub CLI credentials. A provider 409 with exact `Git Repository is empty.` is classified `empty_repository`; no fabricated zeros. Collector diagnostics retain that status, while synchronous HTTP errors preserve 409 with generic safe text.

## Activity collection and persistence guarantees

- Repository Events API is a separate rotating collection family (`activity` in `/api/status`), sharing the existing identity-scoped budgets and deferred-repository/family fairness. Each attempt fetches at most `min(maxPages,3)` pages of 100 and never beyond page 3; a persistent cursor resumes truncated collection, then resets to page 1. Only fixed-origin, locally incremented pagination URLs are used. Validated pages persist independently; a later page failure keeps earlier pages and prior records. Poll delays from `X-Poll-Interval` are retained across restart. Public mode remains anonymous even with a configured token; token/private access never falls back.
- Additive restart-safe migration creates `event_context` (richer canonical records) and isolated `activity_feed` plus a deduplicating read view. Existing `events` rows/columns are unchanged; no startup network access or invented timestamps. Feed collection never modifies daily metric points. Successful metric-window replacement cannot delete feed records, including nondefault-branch activity. Feed errors do not erase or relabel successful metric families.
- PR merge/release publication feed records share canonical IDs with endpoint records, so activity shows one record, preferring authoritative endpoint detail when available. Repeated provider event IDs upsert rather than multiply. `observedAt` identifies the latest successful observation of the retained record and refreshes atomically with its actor/title/context, even when its stable ID was already stored; it is not first-seen time. Unseen records, poll-only cycles and failed reads keep their prior observation time. The actual event `date` and dashboard `lastActivityAt` remain occurrence times, never collection times. Distinct events sharing a timestamp remain distinct. Push events are distinct from commits, never extra commit rows; they cannot change commit counts. Feed-only PR/release records can appear in activity while metric details remain scoped to authoritative endpoint coverage.
- No N+1 commit/user/profile fetches or full-history scans. Historical named stargazer/fork entity endpoints were investigated but not enabled: `/stargazers` with `application/vnd.github.star+json` exposes current stargazers with timestamps, not removed stars or complete event history; `/forks` exposes surviving forks, not all past fork activity. Scanning these under public budgets would compete with existing metrics and cannot establish complete history. Named stars/forks here come from retained Events API observations only.
- Official references: [Events limits and latency](https://docs.github.com/en/rest/activity/events), [event payload types](https://docs.github.com/en/rest/using-the-rest-api/github-event-types), [stargazers and timestamp media type](https://docs.github.com/en/rest/activity/starring#list-stargazers), [fork listing](https://docs.github.com/en/rest/repos/forks#list-forks). Current documentation specifies up to **300 events / 30 days** with **30 seconds–6 hours** latency. Existing API-version pin is unchanged.
